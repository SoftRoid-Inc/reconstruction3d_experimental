# フェーズ2引き継ぎ: 2D抽出結果からの3次元再構成

作成: 2026-09-03 (図面分析セッションの成果引き継ぎ)

## 開発目標(全体)
平面図JPEG → 壁・柱・窓・ドアの位置抽出 → **3次元モデル再構成**。
フェーズ1(図面分析)の環境・評価基盤は完成。ただし2D抽出の精度は未確定
(誤検出が多く、モデル再学習を予定。データ収集は別途進行中)。
**開発の優先度は3D再構成側**: 2D抽出精度の改善検討に時間を使わず、
GTデータを入力として後段の開発を先に進める。

## フェーズ1の成果物(3D化の入力になるもの)

### 1. 正解データ(高品質・整列済み) — 当面の3D化はこちらを推奨
- `28-AAAAA/zumen/1F.json`, `2F.json` (labelme形式)
- ラベル: wall(38/30個) / column(39/22個) / window(6/7個) / door(10/6個) ※1F/2F
- 全て軸平行の矩形、元画像ピクセル座標(2480x1753)
- 整列済み: 共線スナップ・壁ライン帯統一・隙間なし・柱は壁内に内包
  (処理系: `cubicasa/align_gt.py`。窓間の柱=方立では窓が柱エッジで止まる)

### 2. 自動推定(CubiCasa5k) — 現状は精度不十分・再学習待ち
- `cubicasa/results/28-AAAAA/{1F,2F}/s0.75/prediction.json` が現状の最良
- スキーマ: walls/windows/doors/rooms の4点ポリゴン(元画像px座標)+ counts
- 精度(対GT、詳細は `cubicasa/results/28-AAAAA/eval_summary.txt`):
  壁 検出66-93%・pxIoU 0.45-0.57 / 窓 ~30% / 柱 0%(クラス無し)。**誤検出も多い**
- **方針(重要)**: 現行モデルの精度は不十分と判断済み。日本図面での再学習を予定しており、
  学習データ収集は別途(ユーザー側で)進行中。**このリポジトリでのCubiCasa精度改善
  (クロップ・thresholdチューニング等)には時間を使わないこと。**
  3D再構成側は prediction.json と同スキーマを入力インターフェースとして設計し、
  再学習済みモデルが来たら差し替えられるようにしておく

## スケール校正(px → mm)
- 図面は1/50、A4横300dpi相当 → 理論値 1px = 25.4/300×50 ≈ **4.233mm/px**
- ただし必ず図面内の通り芯寸法で検証・校正すること:
  28-AAAAAは横全幅 9100mm(寸法線あり)、28-DDDDDは 8190mm
  → GTの通り芯間の壁中心線距離と比較して係数を決める
- GT壁厚 ~13.4px ≈ 57mm は「作図上の壁線幅」であり実壁厚ではない点に注意
  (実壁厚にしたい場合は木造の標準値 105/120mm 等への正規化を検討)

## 3D再構成の推奨方針(次セッションで計画・実装)
1. **入力**: 28-AAAAAのGT JSON(1F/2F)から開始。自動推定への差し替えは後続
2. **前処理**: px→mm変換、通り芯原点合わせ(1F/2Fの平面位置合わせ。図面ごとの
   作図位置ズレは通り芯グリッド or 外周壁で位置合わせ)
3. **形状生成**:
   - 壁: 矩形を階高で押し出し(階高・天井高は図面注記 CH=2392H, FL+xxx 等を参照。
     不明なら仮定値: 階高2900mm/天井高2400mm を明示して使う)
   - 窓/ドア: 壁体からの開口ブーリアン。高さは注記(2200H等)か建具記号から。
     不明時の仮定: 窓 腰高900+H1100、ドア H2000
   - 柱: 矩形断面のまま押し出し
   - 床/天井スラブ: 部屋輪郭 or 外周から生成
4. **出力**: glTF/OBJ(確認用)。将来IFCも視野
5. **実装環境**: cubicasaコンテナに trimesh 等を追加するか、新サービスを追加
   (Dockerfileパターンは `/home/maren/programming/Dockerfile.cubicasa` 参照)
6. **検証**: 2D平面への再投影がGTと一致すること、寸法線との整合(9100mm等)

## 注意事項
- 元図面・GT・リポジトリ(third_party/CubiCasa5k)は無改変を維持する
- 検討の成果物は reconstruction_3d 配下の専用フォルダに置く(例: `recon3d/`)
- Docker環境の落とし穴は `reconstruction_3d/CLAUDE.md` 参照
